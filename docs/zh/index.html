完整游戏Swarm Night

一款幸存者类 roguelite（吸血鬼幸存者风格）：在围栏环绕的墓园里熬过五分钟，夜晚永不停止地刷出怪物，而你只需移动——所有武器自动开火。开局持有银鞭；击杀掉落经验宝石，经验条满时夜晚暂停，提供三张升级卡：锁定最近怪物的月杖、顺着跑动方向飞出的飞刀、伤害并推开周围一切的蒜环、绕你旋转的灵珠、连锁闪电的唤雷，以及八种被动（移速、生命、磁力、冷却、伤害、护甲、回复、范围）。六种怪物按时间表登场——俯冲的蝙蝠、食尸鬼、骷髅、远程喷吐者、沉重的蛮兽和穿过墓碑的幽魂——另有脚本化的包围圈与怪墙、两名会冲锋并携带宝藏的墓骑士，以及 4:00 登场的骨巨像，其震地一击能把整群怪物掀飞。5:00 黎明即为胜利。WASD / 方向键移动，1 / 2 / 3 或点击选卡；触屏上按住任意位置操控，点按选卡。物理：最多 420 只怪物都是零重力 Space 中的动态圆形，怪群挤压、推挤并绕着墓碑流动，无需一行群集代码；击退是按质量缩放的真实冲量，蒜环与震地是径向冲量，法球、飞刀、唾液与灵珠都是传感器刚体，命中通过 InteractionListener 送达，阵营过滤由传感器组与掩码完成。接触伤害来自 ONGOING 碰撞监听器。3D 模式是月光下的墓园——铁栏、枯树、陵墓、闪烁的灯柱、地面雾气和主角自带的灯光——每种怪物都是由实例化部件组成的关节式低多边形模型，数百只怪物只需寥寥几次绘制调用即可动起来。

在一张大地图上进行的三路攻城建军对战：金币持续累积，屏幕下方是五张部队卡，每打出一张就会放下一队锡制小兵，它们自己出发行军。你从不操控单兵——你决定投什么、投在哪、什么时候投；拿着卡时，这支部队的路线会画在地面上，而你放在自家大门的哪一侧，决定了他们走哪条路。两座主堡之间有三条路，中路各由一座哨塔把守，两翼各有一座中立营地守着的金矿。占下金矿能带来收入并把部署区往前推；主堡在自家哨塔未倒之前始终受护盾保护。十张卡、一位免费统帅，外加三档敌方难度。物理：每个小兵都是零重力 Space 中的动态圆形，人群会自然推挤与绕流；射出的弹丸是传感器刚体，命中通过 InteractionListener 传回，友军伤害由传感器分组与掩码排除，而不是靠一句 if 判断；火药桶引爆时施加真实的径向冲量，飞行单位有独立的碰撞分组。3D 模式下是一片浮在云雾中的草地高台，每种兵种都有独立的关节化低多边形模型。

完整游戏Blade Waltz

圆形竞技场上的《传说》系列风格动作战斗连战：十波怪物、四人小队，而你只操控剑士。自由跑动，打出三段连击（J / 点击），消耗 TP 施放秘技（K —— 中立方向为地面冲击波 Demon Fang，朝向目标为冲刺突刺 Sonic Thrust，背向目标为挑飞斩 Tiger Blade），用 L 防御，当 Overlimit 计量表因造成与承受伤害而充满时，按空格释放秘奥义。普通攻击回复 TP；防御只护住正面；石魔像与头目无视零散的单次攻击。你的AI 队友各司其职：枪兵近身缠斗并连续突刺，弓手拉开距离齐射，贤者治疗、复活并施放火与石魔法，且施法时间可被打断。第十波是一头飞龙，拥有利爪、回旋尾击、火焰吐息、咆哮和召唤鬼火。每个战斗者都是静态墙段环内的动态圆盘；近战由扇形范围判定，而箭矢、弩矢、火球和冲击波则是由 InteractionListener 处理的传感器刚体，阵营过滤全部通过传感器掩码完成。3D 模式下，侧向追踪摄像机取景玩家与目标之间的连线，俯瞰草原上的石制竞技场，所有战斗者都是带关节的低多边形模型。

为什么选择 nape-js？

nape-js 是少数几个同时提供刚体动力学、关节约束（PivotJoint、DistanceJoint、WeldJoint、AngleJoint、MotorJoint、LineJoint、PulleyJoint、SpringJoint）、流体浮力、断裂、基于约束网络构建的软体与布料、射线检测与凸形扫掠、内置角色控制器、用于多人回滚的确定性步进、二进制序列化、回放录制以及独立线程 Web Worker 桥接的 JavaScript / TypeScript 2D 物理引擎——作为单一 ESM 包发布（约 174 KB gzip），带有完整的 TypeScript 类型且零 DOM 依赖。

在寻找 Box2D、Matter.js、Planck.js 或 Rapier 的替代方案？运行浏览器内性能测试进行正面对比，或直接进入交互式示例——物理演示和可玩的小游戏（平台跳跃、MOBA、塔防、弹弓、弹珠台、俯视射击）。

为 AI 辅助开发而生

编程智能体最擅长处理那些可读取、可类型检查、并且能真正运行的库。nape-js 三者兼备。

已提供 llms.txt

完整 API 汇总为一个纯文本文件，位于 /llms.txt，另有完整参考文档 /llms-full.txt —— 这是把文档喂给模型的新兴标准。把 URL 交给你的智能体，无需抓取 HTML。

模型可信赖的类型

全程手写 TypeScript 并启用 strict: true，以生成的声明文件发布。智能体能拿到真实签名和悬停 TSDoc，从而更少臆造不存在的方法。

可在 Node 中无头运行

零 DOM 依赖：智能体可以导入引擎、推进模拟，并直接在终端断言结果 —— 无需浏览器、画布或任何 mock。

确定性，测试才站得住

设置 space.deterministic = true 后，同一平台上相同输入必得相同输出。智能体编写的回归测试会因为正确的原因保持绿色。

已记录的陷阱

反模式指南与排错指南明确列出了模型在物理 API 上最常犯的错误。

API 一览

核心

  • Space — 物理世界
  • Body — 刚体
  • Vec2 — 2D 向量
  • AABB — 包围盒

形状

  • Circle — 基于半径
  • Polygon — 凸包
  • Capsule — 圆角端部
  • Polygon.box(w, h)

约束

  • PivotJoint
  • DistanceJoint
  • WeldJoint
  • AngleJoint
  • MotorJoint
  • LineJoint
  • PulleyJoint

回调

  • InteractionListener
  • BodyListener
  • ConstraintListener
  • PreListener
  • CbType + CbEvent
